# 집중 저하 시간 패턴 — 검토 결과와 1차 구현 범위
작성일: 2026-11-02
대상: [FOCUS_DECLINE_PATTERN_PROPOSAL.md](FOCUS_DECLINE_PATTERN_PROPOSAL.md)
상태: 아래 "채택" 항목은 이 브랜치에 구현되어 있고, 자동 테스트로 검증했다. 의학적 검증은 아니다.

## 1. 제안서 §7 질문에 대한 답

**Q1. 기존 상세 입력 안에 넣으면 원탭 흐름을 유지할 수 있는가? 별도 화면이 정말 필요한가?**
→ 유지할 수 있다. 별도 화면은 만들지 않았다.
- "아차!"는 지금처럼 한 번 누르면 끝이다. 상세 시트 안의 `집중이 흐려졌어요` 체크박스는 기본으로 꺼져 있고, 체크할 때만 보고가 생긴다.
- 아차 기록(`events`)을 집중 저하로 자동 분류하지 않는다. 보고는 별도 컬렉션 `declines`에 저장한다.
- 나중에 입력하는 사후 입력, 하루 맥락, 비교 그래프는 **패턴 탭 안에 접힌 영역**으로 두었다. 돌아보기 화면에는 조용한 바로가기 두 개만 추가했다.

**Q2. 하루 복용 맥락과 개별 사건을 어떤 최소 구조로 연결해야 추정·사후 수정·미기록을 보존할 수 있는가?**
→ 사건과 하루 맥락을 **따로 저장하고, 연결은 저장하지 않고 매번 계산한다.** 사후에 수정해도 연결이 어긋나지 않게 하려는 것이다.
```
declines: [{ id, eventId|null, onsetFrom, onsetTo, onsetCertainty: sure|estimated,
             symptoms[], note, recordedAt, tz, tzOffsetMin, createdAt, updatedAt }]
days: { "YYYY-MM-DD": { dose: { status: taken|not-taken|null, times[1~3], certainty, multiple },
                         sleep: { hours|null, short|null }, meal: { skipped|null, time|null },
                         load: light|normal|high|null, note, tzOffsetMin, updatedAt } }
```
- 발생 시각(`onsetFrom~onsetTo`, 자기보고)과 입력한 시각(`recordedAt`)을 구분한다.
- `dose.status = null`은 **미기록**이다. `not-taken`(복용 안 함)과 다르게 다룬다.
- 복용 시각 후보가 여럿이면 범위로만 계산하고, 평균 시각으로 확정하지 않는다.
- 연결 규칙: 발생 시각 기준 **24시간 안**에 있는 복용(같은 날 또는 전날)이 **딱 하나**일 때만 연결한다. 아래 경우는 연결하지 않고 **제외 이유를 표시**한다.
  - 복용 후보가 여럿인 경우, 후보 중 일부가 발생 시각 이후인 경우 → `연결 불명확`
  - 이날 여러 번 복용한 경우 → `여러 번 복용한 날`
  - 복용 안 한 날, 복용 미기록, 복용 시각 미기록
- 경과시간은 절대 시각의 차이로 계산한다. 그래서 자정이나 일광절약시간(DST)을 넘어도 값이 맞는다.

**Q3. 5일 이후에도 자동 결론 없이 두 축의 원자료 비교만 보여 주는 첫 버전으로 충분한가?**
→ 충분하다고 판단했고, 그렇게 구현했다.
- **날짜를 단위로 센다.** 같은 날 여러 번 기록해도 하루다. 비교를 시작하는 기준은 서로 다른 5일이다(제품상 기준이며, 통계적·의학적 기준이 아니다).
- 고정 시각 축에서는 "가장 많은 날이 겹친 1시간"만 사실로 말한다. 정각 창(예: 16~17시)을 먼저 찾는다. 경과시간 축은 연결 가능한 날이 5일 이상일 때만 말한다.
- **어느 축이 더 우세한지 판정하지 않는다.** 대신 아래 상황을 한계로 표시한다.
  - 복용 시각이 날마다 비슷하면(±30분): "어느 쪽과 더 관련 있는지 구분하기 어려워요"
  - 확실한 입력만 본 결과와 추정 입력을 포함한 결과가 다르면: "추정 시각에 따라 관찰이 달라져요"
- 함께 보여 주는 숫자: 총 관찰 일수, 시각 비교 가능 일수, 경과시간 비교 가능 일수, 추정 입력이 있는 날, 제외 일수와 이유.
- 문구는 "관찰 → 한계 → 해볼 것" 순서이고, 복약 조언·진단·원인 단정은 넣지 않는다. 테스트로 금지어를 검사한다.

**Q4. 07:30/08:30 후보와 16:30~17:00 사례, 자정 경계, 미연결 기록, 일정한 복용 시각, 다중 사건, 과거 백업 병합을 어떻게 검증할 것인가?**
→ 모두 자동 테스트로 확인했다.

| 사례 | 검증 위치 | 기대 결과 |
|---|---|---|
| 복용 07:30/08:30(추정) + 저하 16:30~17:00 | `stats.test`, `e2e` | 경과 **8~9.5시간 범위**, 추정 표시 |
| 전날 23:00 복용, 다음날 01:00 저하 | `stats.test` | 2시간(단순 시각 빼기 아님) |
| 복용 미기록 / 복용 안 함 / 시각 미기록 / 후보가 저하 이후 / 이틀 모두 후보 / 여러 번 복용 | `stats.test`, `e2e` | 연결하지 않고 각각의 이유로 제외 |
| 매일 08:00 복용 | `stats.test`, `e2e` | "구분하기 어려워요" |
| 같은 날 여러 번 기록 | `stats.test` | 하루로 계산 |
| 추정 입력과 확실한 입력의 결과가 다름 | `stats.test` | "추정 시각에 따라 관찰이 달라져요" |
| DST 당일 | `stats.test`(America/New_York에서도 실행) | 실제 경과 시간 기준 |
| 민감 항목이 없는 과거 백업 병합 | `store.test` | 기존 보고·맥락 유지, 같은 날짜는 최신 우선 |

## 2. 채택 / 보류

| 항목 | 결정 | 이유 |
|---|---|---|
| 상세 시트의 "집중이 흐려졌어요"(기본 꺼짐) | 채택 | 원탭 흐름을 바꾸지 않는다 |
| 사후 추가·수정·삭제 | 채택 | 늦게 알아차려도 기록할 수 있다 |
| 하루 맥락(복용·수면·식사·부하), 모두 선택 | 채택 | 미기록과 복용 안 함을 구분한다 |
| 날짜별 발생 시각·경과시간 범위 그래프 + 텍스트 요약 | 채택 | 추정은 빗금·점선 테두리와 "추정" 라벨로 구분하고, 제외 이유는 글자로 쓴다 |
| JSON 백업에서 민감 항목 제외 옵션 | 채택 | 기본은 포함(백업 목적). 공유할 때 체크를 해제한다. CSV에는 원래 포함하지 않는다 |
| 돌아보기 화면에 집중 저하 관찰 노출 | 보류 | 돌아보기는 관찰 하나만 보여 주는 원칙이라, 바로가기만 두었다 |
| 우세한 패턴 자동 판정, 임계값 확정 | 보류 | 제안서대로 확정하지 않는다. 원자료 비교만 보여 준다 |
| 수면·식사·부하를 비교에 반영(보정) | 보류 | 표본이 작아 보정을 주장할 수 없다. 날짜별로 펼쳐 보는 맥락으로만 둔다 |
| 식사 시각 입력 | 보류 | 저장 필드(`meal.time`)만 두고, 화면 입력은 먹음/거름/미기록만 |
| 복용 시각·용량 관련 안내 | 하지 않음 | 의학적 조언의 범위다 |

## 3. 남은 제약
- 기록은 모두 자기보고다. 앱을 연 시간대에 기록이 몰릴 수 있다는 점을 문구로 알린다.
- "가장 많은 날이 겹친 1시간"은 표시용 요약일 뿐, 통계적 검정이 아니다.
- 복약·증상 기록은 이 브라우저에만 저장되고, 외부로 보내지 않는다. 기기 사이 동기화는 없다.
