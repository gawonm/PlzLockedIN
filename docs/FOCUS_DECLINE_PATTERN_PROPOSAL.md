# PlzLockedIN — 집중 저하 시간 패턴 기능 제안
작성일: 2026-11-02
상태: Claude Code 검토용 제안. 구현 지시·확정 명세가 아니며, 아래 기능은 이 문서 작성으로 구현되지 않는다.

## 1. 배경과 검토 목적
오후 특정 시간에 집중이 급격히 흐려진다는 자기 관찰을, 부담 없이 여러 날 비교할 수 있게 하는 방향을 제안한다. 기존 [구현 인수인계](CLAUDE_CODE_DESIGN_HANDOFF.md)의 “알아차린 순간, 하던 일로 돌아가기”와 원탭 기록 원칙을 유지한다.

공개 저장소용으로 개인 관찰의 날짜·약품명은 제외했다. 다음은 시간 관계를 설명하는 익명화 사례이며 실제 사용자 데이터나 기본값으로 앱에 넣지 않는다.

> 집중 저하를 16:30~17:00 무렵 알아차렸다. 복용 시각은 07:30 또는 08:30으로 기억이 불확실하다. 가능한 경과시간은 약 8~9.5시간이다. 07:30이면 9~9.5시간, 08:30이면 8~8.5시간이며, 두 후보를 임의의 평균 시각으로 확정하지 않는다.

이 한 번의 기록만으로 반복 패턴이나 원인을 판단할 수 없다. 약효 감소·인지 피로·리바운드는 향후 관찰을 위한 가설 이름일 뿐이다. 앱은 어느 가설이 맞는지 판정하거나 의학적 진단, 복용 시각·용량 변경을 권고하지 않는다.

## 2. 제품 방향: 먼저 기록하고, 필요하면 나중에 보충
- 기존 “아차!” 버튼은 지금처럼 한 번 누르면 바로 저장된다. 복약 정보나 증상 선택을 완료 조건으로 붙이지 않는다.
- 기존 선택 상세 또는 종료 후 돌아보기에서 “집중이 흐려졌어요”를 추가할 수 있는 방안을 검토한다. 일반 이탈 로그 전체를 집중 저하 사건으로 자동 분류하지 않는다.
- 복용 정보와 하루 맥락은 선택 입력으로 두고, 이탈 기록마다 반복해서 묻지 않는다. 복약 기록을 쓰지 않아도 기존 앱을 온전히 사용할 수 있다.
- 사후 입력·수정·건너뛰기를 허용한다. 입력 중 강제 닫힘이나 자동 설문·알림을 추가하지 않는다.
- 집중 중에는 그래프를 숨기고, 종료 후 돌아보기에는 관찰 하나만 제시한다. 상세 비교는 기존 패턴 화면에서 선택해 펼치는 방향이 적합하다.

## 3. 기록 후보
필드명과 저장 구조는 검토 사항이며 아래 표는 기록 의미를 정의한다.

| 항목 | 제안하는 표현 | 입력 원칙 |
| --- | --- | --- |
| 복용 시각 | 날짜 포함 시각 + 확실/추정, 필요하면 후보 시각 또는 범위 | 선택. 모름·미기록과 복용하지 않음을 구분하며 미기록을 미복용으로 처리하지 않음 |
| 집중 저하 발생 시각 | 지금 또는 사후 지정 시각/범위, 확실/추정 | 자기보고 시점. 버튼을 누른 기록 시각은 별도로 보존 |
| 체감 증상 | 산만함 / 졸림·피로 / 무기력 / 짜증·초조 / 다른 일로 이탈 | 선택형 복수 선택. 선택 없음은 증상 없음이 아님 |
| 수면 | 수면 시간 또는 평소보다 부족했는지 | 선택·사후 입력 |
| 식사 | 식사 시각 또는 거름 여부 | 선택·사후 입력 |
| 수업·작업 부하 | 가벼움 / 보통 / 높음, 필요하면 짧은 메모 | 선택. 객관적 부하 점수로 해석하지 않음 |

입력 시각과 실제 발생 시각을 구분하면 늦게 기록한 날도 비교할 수 있다. 날짜·당시 시간대 정보를 보존하고, 자정 전후나 시간대 변경을 단순 시각 빼기로 계산하지 않는 것이 필요하다. 복용과 사건의 연결이 불명확하거나 여러 복용 기록이 있으면 임의로 연결하지 않고 경과시간 비교에서 제외하는 방안을 검토한다.

## 4. 5일 이상 관찰한 뒤 비교할 두 축
5일은 비교를 시작하기 위한 제품상 제안 기준이며, 통계적 신뢰성이나 의학적 타당성이 확보되는 기준이 아니다. 같은 날 여러 번 기록해도 여러 날로 세지 않는다.

1. **고정 시각 패턴:** 날짜별 집중 저하 발생 시각이 16~17시처럼 비슷한 시간대에 모이는지 살펴본다.
2. **복용 후 경과시간 패턴:** 복용 정보와 연결할 수 있는 날짜별 사건이 복용 후 비슷한 경과시간에 모이는지 살펴본다.

고정 시각 요약은 발생 시각이 있는 서로 다른 5일 이상, 두 축 비교는 복용 정보까지 연결 가능한 서로 다른 5일 이상을 출발점으로 제안한다. 총 관찰 일수·비교 가능 일수·추정 입력 일수·제외 일수를 함께 표시한다. 기존 일반 인사이트의 15건·3일 기준을 이 기능의 근거로 대체 사용하거나 이번 제안만으로 수정하지 않는다.

복용 시각이 매일 비슷하면 고정 시각과 경과시간이 함께 움직여 둘을 구분하기 어렵다. 5일을 넘겨도 “현재 기록으로는 두 패턴을 구분하기 어려워요”가 적절할 수 있다. 비교를 위해 복용 시각을 바꾸라고 유도하지 않는다.

추정 시각은 점이 아닌 범위/후보로 보여 준다. 확실한 입력만 본 결과와 추정 입력을 포함한 결과가 다르면 “추정 시각에 따라 관찰이 달라져요”라고 표시한다. 관측 범위가 크게 겹치면 우세한 패턴을 선정하지 않는다. 자동 분류 알고리즘이나 임계값은 이 제안에서 확정하지 않는다.

수면·식사·부하는 함께 살펴볼 맥락이다. 적은 표본으로 교란변수를 보정했다고 주장하거나 복용과 집중 저하의 인과관계를 도출하지 않는다. 특정 시간에만 앱을 켠 경우 그 시간의 기록이 많은 것은 관찰 기회의 차이일 수 있다. 여러 사건이 있는 날의 모든 점을 표시하되, 하루의 많은 클릭이 여러 날의 반복으로 과대해석되지 않게 한다.

## 5. 시각화와 개인화 문구
- 날짜별 발생 시각과 복용 후 경과시간을 나란히 비교하는 작은 점/범위 그래프를 검토한다. 추정·미기록·제외 상태는 색뿐 아니라 라벨로 구분하고 텍스트 요약도 제공한다.
- 두 그래프는 같은 비교 대상 날짜를 사용하고, 추가로 표시한 미연결 날짜는 명확히 구분한다. 날짜마다 수면·식사·부하는 사용자가 펼쳐 볼 수 있다.
- 기록 수를 집중력 점수나 실제 이탈 빈도로 표현하지 않는다. 미기록을 “집중 저하 없음”으로 해석하지 않는다.
- 개인화 인사이트는 기존처럼 **관찰 → 한계 → 해볼 작은 전략**을 따른다. 전략은 사용자가 선택하는 휴식·작업 순서 점검 등이며 복약 조언을 포함하지 않는다.

문구 예시(예시 수치는 실제 데이터로 교체할 대상이며 하드코딩하지 않음):
> 비교 가능한 6일 중 4일에 16~17시 집중 저하를 기록했어요. 복용 시각이 비슷하고 일부는 추정이라, 시계 시간과 복용 후 경과시간 중 어느 쪽과 더 관련 있는지는 아직 알기 어려워요. 다음에는 그 시간대의 작업량과 휴식 여부를 함께 돌아볼 수 있어요.

자료 부족 시:
> 아직 관찰 중이에요. 현재 비교 가능한 날은 2일이에요. 미기록 시간의 집중 상태는 알 수 없어요.

## 6. 기존 구조와 검토 범위
현행 README와 js/stats.js의 일반 인사이트 기준을 확인했다. 기존 HTML/CSS/JavaScript와 로컬 우선 저장 구조 안에서 검토할 수 있으며, 새 프레임워크나 외부 AI 분석을 전제로 하지 않는다.

| 향후 채택 시 살펴볼 곳 | 검토할 영향 |
| --- | --- |
| index.html, styles.css, js/app.js | 원탭 유지, 선택 상세·사후 수정, 돌아보기와 패턴 화면, 키보드 접근성 |
| js/store.js | 선택 필드 보존, 입력 검증, 날짜·시간대·불확실성, 기존 데이터 호환, 병합·복구·JSON/CSV 내보내기 |
| js/stats.js | 일반 이탈과 집중 저하 구분, 비교 가능한 날짜, 경과시간 범위, 자료 부족·구분 불가 처리 |
| tests/store.test.mjs, tests/stats.test.mjs, tests/e2e.mjs | 저장·분석·원탭 흐름 회귀 검증과 기존 fixture 호환 |
| sw.js, README.md | 채택·구현 후에만 오프라인 갱신 및 실제 동작 설명 반영 |

이번 변경 범위는 이 제안서 한 파일이다. 실행 코드·설정·기존 스키마·테스트·내보내기 형식에는 변경이 없다.

복약·증상은 민감한 개인 기록이다. 채택 시 기존 로컬 저장 원칙을 유지하고, 사용자 데이터·백업·실제 관찰 사례를 저장소나 외부 분석 서비스에 보내지 않는 것이 적합하다. 내보내기에 민감 항목이 포함되는지 사용자가 알 수 있게 하는 방안도 검토한다.

## 7. Claude Code가 검토할 질문
- 기존 상세 입력 안에 넣으면 원탭 흐름을 유지할 수 있는가? 별도 화면이 정말 필요한가?
- 하루 복용 맥락과 개별 사건을 어떤 최소 구조로 연결해야 추정·사후 수정·미기록을 보존할 수 있는가?
- 5일 이후에도 자동 결론 없이 두 축의 원자료 비교만 보여 주는 첫 버전으로 충분한가?
- 채택할 경우 07:30/08:30 후보와 16:30~17:00 사례, 자정 경계, 미연결 기록, 일정한 복용 시각, 다중 사건, 과거 백업 병합을 어떻게 검증할 것인가?

검토 결과는 채택/보류 항목과 이유, 필요한 최소 변경 범위로 정리할 수 있다. 이 문서는 구현 완료나 의학적 검증을 의미하지 않는다.
